For the engineer picking this up. Read this first, then CLAUDE.md (the project's rules; Claude Code loads it by itself every session), then AGENTS.md (this Next.js version is new: read node_modules/next/dist/docs before writing app code).

## What it is
Noun ART (https://art.incivera.ai) is Noun Naturals' content system. It runs the weekly content calendar in "spaces" (it replaces Daryna's Notion), raw clip upload with directions drawn on the clip, edited video versions, review and approval, then posting to TikTok, Instagram and Facebook, with post numbers and later AI agents. It is used mostly on phones and iPads by an editing agency in Ukraine (walkthrough with them Monday Nov 16). Khaled is the owner, not a coder: he tests the published app and clicks Pull and Republish on Replit himself.

## The rules that matter most (all in CLAUDE.md)
1. **Published vs test run.** `usesRealContent()` in `src/lib/database-target.ts` is true only in the published app (REPLIT_DEPLOYMENT=1). The published app reads and writes real content and shows NO demo data anywhere. A test run (localhost, the Replit workspace) signs in for real but shows only demo data and never reads or writes real content.
2. **One content source.** `src/lib/content` is the only code allowed to import `src/lib/sample` (ESLint rule plus a scan test; the allow list `src/lib/content/sample-importers.mjs` may only shrink).
3. **Server actions** check in order: signed in, `usesRealContent()`, a permission key, then write with the person's own Supabase session (row level security stays the lock). Pattern: `src/lib/content/calendar-actions.ts`. Never a hard delete (`deleted_at`, `purged_at`).
4. **Permissions, not roles.** Code checks keys from `src/lib/access/permissions.ts` (52 keys in code, 51 in the live database: files.manage is live with supabase/migrations/20261122000000_files_and_reader.sql, and posting.resolve waits for supabase/drafts/20261119300000_meta_posting.sql, which needs a timestamp later than 20261122000000), never role names. A new key goes in that file and in the database seed in the same change. Prebuilt roles: Owner, Admin, Strategist/Editor, Viewer, plus custom roles built on the Roles page.
5. **Big files never pass through our server**: browsers upload straight to storage with signed links (raw footage to a Google Shared Drive, edited versions to Cloudflare R2).
6. Nothing is posted, sent or messaged without Khaled's yes. Every OAuth callback gets three addresses: https://art.incivera.ai, https://noun-art.replit.app, http://localhost:3000. No page may be indexed by search engines.
7. Git: never chain pull, add, commit and push in one command; check for conflict markers before committing; do not commit `.claude/launch.json` (local tooling). Commits use the noreply identity already in this repo's git config.
8. Before every push, two separate reviewers (a Sonnet and a Haiku agent, or a second engineer) check the change for crashes. Fable 5.2 plans builds; Opus or Sonnet agents write the code.
