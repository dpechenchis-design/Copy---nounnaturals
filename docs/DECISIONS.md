# Decisions

What we chose and why. Newest at the top. One block per decision.

## November 17, 2026 (TikTok Video address: URL prefix on r2.dev, owner approved)

- **TikTok checks our video address as a URL prefix on R2's own public address, not a DNS domain.** The owner's steps: turn on the Public Development URL on the R2 bucket, put that address (like https://pub-<hash>.r2.dev, no path) in Replit Secrets as R2_PUBLIC_BASE_URL, Pull and Republish, then Settings, Integrations, TikTok, Video address, press Verify. One press: the app adds the address at TikTok, puts TikTok's check file in the bucket and asks TikTok to check. Why: no DNS move, one click, and team playback stays private (the app always plays through signed links; the public address is only for TikTok's one download per post). This supersedes the media.incivera.ai DNS plan below (kept as history, not deleted). Risk: a public address never expires and covers every file in the bucket, including unapproved edits and older versions. Anyone with a file's exact address can open it. There is no listing, and the names carry long random parts, so they cannot be guessed. Cloudflare calls r2.dev a development address and rate limits it: a custom domain later if it throttles. Not yet verified: whether TikTok accepts an r2.dev prefix; the first Verify shows it.

## November 17, 2026 (TikTok API for Business: connector and posting built)

- **TikTok runs on TikTok API for Business, built on a branch, not pushed.** Noun ART is approved there (docs/TIKTOK.md). The old developers.tiktok.com code and the keys TIKTOK_CLIENT_KEY and TIKTOK_CLIENT_SECRET are gone; the old app can be deleted. The new keys are TIKTOK_BUSINESS_APP_ID and TIKTOK_BUSINESS_APP_SECRET. Why: the old door refuses a brand posting to its own accounts; the new one posts publicly.
- **Two phase posting, with the switch right before publish.** The run claims the post, opens a try, then flips the one time switch (claim_post_publish) immediately before the single publish call, and afterwards only asks for the status. Why: a post must never go out twice, even if the run dies half way.
- **Only a clear no fails a post.** A refusal TikTok clearly gave (code 40000 to 49999, answer under 500) fails with one plain sentence. A timeout, an unreadable answer or a server error never counts as failed: the post waits, and after a few minutes shows "Needs a check". Why: failing a post that actually went out would invite a second post.
- **Daily cap per account is the smaller of its daily cap and 15, default 3.** New TikTok accounts get 3; TikTok's own limit is 15 a day. A cap of 0 posts nothing. Videos waiting in TikTok's drafts count too.
- **A Shop product link goes to drafts and ends as Finish in TikTok.** The API cannot add a Shop link, so a person finishes the post in the TikTok app. It never shows as posted.
- **"Your brand" is on by default, "Paid partnership" off; comments, duet and stitch follow the box, but an account that turns one off wins.** The AI label comes from the video's own label. Assumed from the open decisions 4 and 12 in docs/TIKTOK.md; the owner can still change them.
- **The Video address is read live from TikTok and nothing is stored.** (Superseded the same day: first a TXT record plan, now one Verify press on an r2.dev prefix, see the entry above.) Verify asks TikTok again. Why: one source of truth, and no table to go stale. Posting is "Being connected" until the address is verified.
- **Old app accounts are adopted by username on Reconnect.** An account connected with the old app comes back with a different TikTok id and the same username; the row is kept, with its posting permissions. Until then it shows "Connected with the old TikTok app" and is not posted to.
- **A duplicate connect adds no row.** Connecting an account that is already live says "already connected" and silently saves the newest tokens. Why: the owner wants no duplicates, and fresh tokens do no harm.
- **No database change and no new permission key.** The existing social_accounts, account_tokens and posting tables hold everything. TikTok posting goes live only when the Meta posting draft is live (it holds the switch and the run's lease).
- **The Spark Ads and mentions scopes are left out for now.** Why: not needed to post. Every later scope needs TikTok's access form again, so it is a later decision. Also deferred: comments, insights and the video library, live updates, sounds in the box, photo posts, a daily token refresh timer, and finding an unclear post through the video list.
- **Facts not yet verified.** TikTok's own pages could not be read, so the numeric error codes, the draft status and the scope separator come from TikTok's open source SDKs. The first real test, on a throwaway account, reads the real answers.

## November 16, 2026 (Upload/Files and the Gemini reader, owner said go)

- **One sidebar item, "Upload/Files", with a switch.** Upload and Files are two views of the same place, so they share one item and a small switch at the top; the content team inbox is one press away. On the phone bar the item is called "Upload", because the long name does not fit under the round button. Why: fewer places to look, and the team thinks of it as one job.
- **Upload is a mass upload into a space's New uploads. It never asks for a day.** The person picks the space and drops everything (up to 200 files or a folder), or drops onto any folder in Files. Why: footage for Monday is often shot on Wednesday or uploaded weeks later, so a day picker only made wrong answers. This replaces the once per day raw inbox.
- **Files is the Shared Drive "Noun ART (Content System)" inside the app.** Every folder and file shows, with New uploads first, then each week with its Raw, its days and a folder per card, then the team's own folders. The team makes, renames, moves and removes its own folders (Remove goes to Google Drive's trash, with Undo); the folders the app makes are locked. Why: nobody should need to open Google Drive to find a clip.
- **A Week folder made in Files never makes a Calendar week.** Weeks are made in the Calendar only; Files follows the Calendar, not the other way round. Why: one source of truth for the plan.
- **Gemini only transcribes. It never watches the video.** Gemini Transcribe turns the sound into text, then Gemini Hydrogen reads that text and writes a short title, one or two lines, and the cards it could belong to, in any week. Why: hearing costs about half a cent a minute, watching would cost many times more, and the words are what matches a clip to its script.
- **No speech means a "No sound video" at $0.** The reader checks for sound before it calls Gemini; a silent clip or a photo is never sent, costs nothing, and waits in the inbox for one tap.
- **90% or more files itself, with Undo.** When Gemini is that sure of the card, the original moves to that week's Raw folder and a shortcut goes into the card's folder; a file in a team folder stays where the team put it and only gets the shortcut. Anything under 90% waits in the content team inbox for one tap (Confirm, Pick another or Make a card). Every automatic filing has Undo, and Undo presses are counted so we can see if 90% is the right line.
- **$5 a day, and only the owner changes it.** The reader stops at the daily limit and says "Waiting: daily limit reached"; uploads never wait for Gemini. The limit and the spend show in Settings, AI costs.
- **The cost shows on every file, to everyone.** Each file, each drop and each folder shows what Gemini cost, with the model's logo.
- **Old folders are read one press at a time.** What was in the drive before is not read by itself; "Read this folder with Gemini" shows the estimate first and reads only that folder. Why: the old footage is large and the owner decides what is worth the money.
- **The reader is the Cloud Run job art-reader on our own Google Cloud.** Replit cannot run background work and Gemini cannot open a Drive file by itself, so a small job on the noun-art Google Cloud project pulls only the sound, calls Gemini and files the clip. It starts after an upload and a schedule wakes it every 5 minutes; the owner sets it up once with worker/setup.sh. Our own keys, no new vendor.
- **Counts.** supabase/migrations/20261122000000_files_and_reader.sql is live (owner approved, Nov 16 2026): it added one table, raw_clip_moves (92 with the two Frame.io tables), and the key files.manage. The live database has 92 tables and 51 permission keys; with posting.resolve from the Meta posting draft (which needs a timestamp later than 20261122000000) the code lists 52. Strategist/Editor holds files.manage, so 31 of 51 live and 31 of 52 in code.
- **Nothing already uploaded is read (owner, Nov 16 2026).** Gemini never reads a file uploaded before this migration, matched or not; only files uploaded after it go to the reader.
